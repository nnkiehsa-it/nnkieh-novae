# Novae repository structure

This document is the maintained map of the repository. Read it before broad searches and update it whenever files or responsibilities move.

## Runtime and entry points

- `package.json` / `bun.lock` — Bun 1.4 package management with a pinned install graph; Node 24 remains the Next.js, build-script, and Worker runtime alongside Next.js 16.3, React 19.2, TypeScript 7, Tailwind CSS 4, Radix/shadcn primitives, Motion, Vditor 4 WYSIWYG Markdown editing, Serwist, Vitest, and Playwright.
- `src/app/` — Next App Router. Route `page.tsx` files assemble views and forward events; they do not import `services/` directly.
- `src/app/layout.tsx` — root metadata, stable immersive iOS viewport/status-bar configuration, Inter/Roboto Mono plus HarmonyOS Sans TC split-font loading, global providers, global CSS, and nonce-bound critical Managed Turnstile preconnect/loading before hydration.
- `src/app/globals.css` — website-aligned cool blue light/dark surfaces, semantic brand actions and custom accent themes, compact typography and radius scale, restrained elevation, safe-area and stable PWA viewport sizing, keyboard-aware navigation, input-modality focus handling, and the shared discussion composer dock.
- `src/assets/fonts/harmonyos-sans-tc/` — generated, project-character-scoped HarmonyOS Sans TC Regular, Medium, Semibold, and Bold shards plus CSS; refreshed by `scripts/generate-harmonyos-subset.mjs`.
- `src/styles/motion.css` — every motion recipe in the product, written entirely in terms of a ladder it does not own. Covers route push/pop and replacement, the press vocabulary, menus, dialogs and the mobile bottom sheet, tabs, switches, toasts, skeleton-to-content handoff, success confirmation, and reactions. The pacing is iOS: a touch is acknowledged in a tenth of a second, a control settles in a quarter, anything genuinely new — a route, a panel, a toast, content replacing its own skeleton — takes long enough to be read as arriving, and a layer presented over the current place takes the longest. What it deliberately leaves alone matters as much: furniture does not fade in, lists do not stagger, and anything already on screen when a route arrives is carried by the route transition instead of animating again underneath it. Reduced-motion fallbacks are centralized here.
- `src/styles/vditor-editor.css` — scoped Vditor toolbar, WYSIWYG content, focus, light/dark token, mobile keyboard, reduced-motion, and loading-surface overrides aligned with Novae's design system; wide tables scroll inside the bounded editor and table controls scroll without being clipped.
- `src/app/sw.ts` — Serwist service worker; `next.config.mjs` compiles and registers it at `public/sw.js`, while WOFF2 font shards stay outside install-time precaching and load normally through their unicode ranges.
- `src/proxy.ts` — per-request nonce CSP for Next hydration, strict production script execution, Firebase App Check/reCAPTCHA, Cloudflare Turnstile, and local-emulator development connections.
- `next.config.mjs` — public environment injection, static security headers, image hosts, and Serwist integration.
- `next-env.d.ts` — ignored framework-generated type references; Next.js regenerates the file for the active development or isolated verification output directory.
- `components.json` — shadcn/ui aliases and Tailwind 4 configuration.
- `public/` — brand identity assets (`logo.svg`, `logo.png`, `favicon.ico`, `apple-touch-icon-180x180.png`, `maskable-icon-512x512.png`, `pwa-*.png`), constellation login artwork, and compiled service worker runtime.
- `vercel.json` — Vercel Next.js framework configuration with an explicit frozen Bun install command for CLI and hosted builds.

## App Router

- `src/app/login/` — focused Google sign-in presentation with the website's blue brand statement and desktop constellation image; the mobile authentication path stays compact.
- `public/novae-constellation.webp` — original website brand artwork, reused on the desktop login surface with reserved image dimensions.
- `src/app/(protected)/layout.tsx` — authenticated application guard and shared shell boundary.
- `src/app/(protected)/setup/` — admin-only idempotent category setup with completion recovery in `use-initial-setup`; first-visit language selection happens through the shared locale gate before any route.
- `src/app/(protected)/issues/` — feature-guarded issue redirect, feed, composer, and detail routes.
- `src/app/(protected)/facilities/` — feature-guarded facility feed, composer, and detail routes.
- `src/app/(protected)/announcements/` — announcement feed, composer, and detail routes.
- `src/app/(protected)/notifications/` — merged broadcast/admin/user notification presentation with an immediately prefetchable route-loading shell.
- `src/app/(protected)/settings/` — account, appearance, language, install, push, and resource settings using the full shared desktop content width.
- `src/app/(protected)/admin/` — the administration area, one responsibility per route: `/admin` is both the landing page and the merged platform overview, and `content`, `platform`, `people`, `audit`, `system` and `policies` each own one screen, one permission gate, and one save. `layout.tsx` gates the area, mounts the apply-progress panel once, and guards departure from an unsaved draft; each route carries a geometry-matched `loading.tsx`. The separate `/dashboard` route and the tabbed `/admin/management` route it replaced are gone, with no compatibility redirects.

## Presentation components

- `src/components/motion/resize-motion.tsx` / `state-transition.tsx` / `stagger.tsx` — opt-in, height-only state-container resizing plus shared content entry/exit and dynamic-list presence animation; viewport reflow is excluded, physical card frames survive state replacement, observers clean up after disconnected nodes, and reduced motion is honored.
- `src/components/ui/feed-list.tsx` — persistent physical card slots for loading, content, error, and empty states; domain content stays keyed by entity inside the retained frame.
- `src/components/ui/detail-layout.tsx` — persistent detail content and reaction/timeline cards; record loading replaces only their contents.
- `src/components/ui/skeleton-rows.tsx` — shared pending rows for discussions and administrative lists. Skeleton animation phases follow the document clock.
- `src/components/ui/list.tsx` / `list-controls.tsx` — the grouped list: a card owns the gutter, `.rule-list` draws the hairline between rows, and the bleeding tint layer on `.t-row` lets a press or a selection reach the card's rounded corners while the dividers stay inset. Rows are whole-row targets; a choice is marked with a check that fades in rather than a box. A group carries no explanatory sentence: the rows say what they are. `ListRowGroup` is the one way a setting reveals further rows, so they travel through their own height in both directions instead of appearing and vanishing. Settings, notifications and administration screens are built from these instead of label-above-a-box forms.
- `src/components/ui/record-list.tsx` — the search field, card, first-read/empty/failed states and paging that a searched administrative record list wears. What a record looks like belongs to the screen that owns it: a person and a recorded action are each two lines rather than a row of columns, because as columns both became a stack of labelled fields on every screen narrower than a desktop. People are read two abreast through the `.rule-grid` recipe, so a wide card stops running off the bottom of the screen.
- Custom accent controls, provider, persistence module, and the separate `ResizableCard` implementation are removed. All cards use `Card`; selected tabs use the fixed brand accent.
- `src/components/ui/` — business-free shared primitives. Primary actions use the card surface with a defined border; accent remains for brand emphasis, selected states, and links. Secondary/cancel controls use neutral surfaces and destructive actions retain warning color. Fields, overlays, tabs, menus, badges, skeletons, page states, loading indicators, image presentation, and branding share semantic tokens. `page-state.tsx` keeps each route's main header pinned beneath the safe area and owns its height-following progressive backdrop blur, so scrolling content is softened behind the header without filtering the foreground title or controls. A subpage's back control is handed to the header as its `lead` rather than placed above it, so it is pinned with the title instead of scrolling behind the veil the header draws. `card.tsx` and the shared resize observer preserve text geometry during resizing; `skeleton-reveal.tsx` overlays placeholders on the actual final field footprint.
- `src/components/ui/dialog.tsx` / `alert-dialog.tsx` — `DialogContent` takes a `presentation` of `centered` or `sheet`; a sheet owns the bottom edge on a mobile layout and stays a centred dialog above it, and action, status, and editor overlays use it. A sheet's content stays mounted while it closes, so it leaves along the edge it arrived on. Destructive confirmation keeps `AlertDialog`, which is always centred, because a sheet invites dismissal.
- `src/components/ui/decision-sheet.tsx` — one decision, made once: the outcomes as choice rows, the sentence it is recorded with as the last row, and a single control that is the only thing that writes. `DecisionSheet` is that form arriving as a sheet, and `DecisionForm` the same form inside a sheet that also has something to report — account restriction, proposal moderation and facility conclusion are the same act and now the same surface.
- `src/components/ui/disclosure.tsx` — a row that opens onto more of itself, owning the mark that turns and the height the content travels through in both directions; policy revisions, the long table list and provider payloads all use it instead of swapping a block in and out of the document.
- `src/components/ui/feed-card.tsx` — shared compact title/author/action geometry and grid for proposal, facility, announcement, loading, and empty cards; `FeedProgress` keeps deadline and count in one row so optional deadlines cannot shift the footer.
- `src/components/ui/status-distribution.tsx` — the share of a category held by each status: one proportional bar plus the figures beneath it, fed by counts the list snapshot carries. `status-badge.tsx` owns the status colour tokens both of them read.
- `src/components/ui/feed-toolbar.tsx` — one search/sort control pair used by live feeds and disabled route placeholders, without a redundant outer card. The field itself lives in a `popover.tsx` panel behind a search trigger at every width, so `PageHeader`'s `toolbar` slot keeps both controls beside the status tabs instead of on a line of their own; a dot on the trigger marks a query that is still applied.
- `src/components/ui/list.tsx` — the grouped list: rows that report, rows that lead somewhere, and rows that change something. A row that writes never takes the whole width as its target: `ListMutationRow` reports and opens, and `RowAction` is the single glyph beside it that acts, so a list of destructive controls cannot be set off by a stray tap.
- `src/components/ui/progress-bar.tsx` — how far along something is, as one line; shared by the background-work panel and the operations screen's running jobs.
- `src/components/ui/popover.tsx` — the shared floating panel primitive: dropdown geometry and motion for content that is a small form rather than a menu.
- `src/components/ui/image-preview.tsx` — the one way an image is shown before it is opened: a square tile the picture is fitted inside rather than cropped to, the grid those tiles align in, and the lightbox opening one leads to. Shared by attached content images and composer attachments.
- `src/components/ui/detail-card.tsx` — shared detail header and body for proposals, facilities, announcements, and their loading placeholders; badges, title, and metadata reserve the same minimum heights. `DetailBadge` is the neutral pill each of them opens with, so a proposal's category, a facility report's category, and an announcement naming itself are one shape.
- `src/components/motion/` — product-consumed animated numbers and reactions, the route surface, persistent navigation feedback, list entry/exit/reordering, and non-overlapping state replacement transitions. `navigation-feedback.tsx` answers a tap on a destination by marking the tapped control itself with `data-navigating` until the route commits, so the answer travels with the control as the page scrolls, and it starts on the click, which a touch that becomes a scroll never produces; the progress line waits out a control rung before it appears, so a route that commits immediately never draws one. `route-surface.tsx` derives navigation direction from the two pathnames and publishes it on the page that arrives, so an in-app back button, the browser's Back and Forward buttons, and the iOS edge swipe all resolve to the same push or pop. The reveal is one animation on that page, in the live document: a child arrives from the trailing edge, its parent from the leading one, and a replacement simply appears. Nothing is captured — a document snapshot rasterises both pages exactly when the browser is fetching and rendering the route that was asked for, and suspends hit testing for the length of the animation. Reaction hooks still update immediately, confirm in the background, and roll back with retry feedback on failure.
- `src/components/app-providers.tsx` — root client providers plus global input-modality ownership; keyboard activity enables focus-visible presentation, while pointer movement/down immediately returns controls to pointer presentation.
- `src/components/app-shell.tsx` / `liquid-nav.tsx` — desktop and mobile navigation. Selection follows the committed pathname; Next Link owns pending feedback and shared-layout motion moves the selection. Primary links request a live, in-place route reveal so the dock remains clickable during rapid navigation. The dock is live throughout a navigation — nothing is captured, so it never leaves the hit-test tree and never has to be produced again afterwards. It animates nothing of its own: it belongs to the route, and the route change already covers it or uncovers it. On mobile the route surface owns the page gutters and vertical padding, and the floating dock appears exactly where `route-hierarchy.ts` says primary navigation belongs. The shell supplies only the labels and icons for those destinations, and it mounts the two warming hooks — the route set every session needs, and the intent prefetch that answers a pointer on any link at all, which is why the dock no longer asks for its own destinations. Because both bars are lifted out of the document flow and are positioned from the live viewport height, the selection is measured inside the bar and moved with an explicit transform rather than by comparing two viewport rectangles taken at different moments — which is what used to send it flying in from wherever the bar had been. With no control selected it fades out where it stands. Route headers retain their sticky progressive blur.
- `src/lib/route-hierarchy.ts` — the single description of how routes nest, including the fact that settings owns the administration area whose URLs sit outside `/settings`, and the fact that `/issues` is a doorway that forwards to a category rather than a place of its own, so crossing it carries no direction. It also names the destinations primary navigation points at, so whether a route reveals in place, and whether the floating dock belongs on it, are answered from one table rather than from a regular expression in the shell. Navigation highlighting, navigation direction, and the dock all read it; it performs no routing of its own.
- `src/lib/share.ts` — shares the current page, marking the link so the tab it is opened in knows it arrived from somebody else. Inside a messaging app's browser the marker is written into the address instead of removed, so the handoff carries it whether it goes through Novae or through the app's own menu; nothing arrives in one of those browsers except through a link somebody sent. Links shared before the marker existed are recognised by shape instead: a tab with no history of its own that opened straight onto one piece of content.
- `src/lib/navigation-memory.ts` — remembers the immediately preceding in-app pathname solely to choose safe detail and administration return targets, and performs the return itself. Route rendering and browser history remain native App Router responsibilities.
- `src/components/issues/` — issue cards, detail content/actions, moderation presentation, and the administrator-only local author-visibility control used when presenting a proposal.
- `src/components/facilities/` — facility cards, shared detail content with status-aware conclusion presentation, status-dialog presentation, and the category and location fields a facility report adds to the shared composer, which take the same pending state the rest of the composer does.
- `src/components/announcements/` — announcement cards.
- `src/components/settings/` — `account-section.tsx`, `appearance-section.tsx`, `notification-card.tsx` and `settings-links.tsx`: the whole route is one stack of grouped lists, including who is signed in, how the app looks and reads, whether it is installed, and signing out. The route has no `loading.tsx`: it waits on nothing but its own prefetched chunk, so a skeleton would only be a second copy of the page to keep in sync.
- `src/components/notifications/notification-skeleton.tsx` — route and local notification loading rows that share the resolved list container, padding, icon column, and text anchors.
- `src/components/admin/admin-page.tsx` / `admin-page-skeleton.tsx` / `admin-list-skeleton.tsx` — the frame every administration route wears, and the matching loading shell each route's `loading.tsx` renders. The shell carries the real back control rather than a placeholder of one, because it works while the rest of the route is still arriving. The skeleton reads no session and no query string, so a route-loading fallback stays statically prerenderable.
- `src/components/setup/` — setup step chrome and reusable category draft editors.
- `src/components/admin/` — one component set per administration route: the merged overview (`admin-overview.tsx`, `overview-metrics.tsx` — where each figure for the period opens onto the share of the period's activity that it counts, out of the reading the screen already holds, instead of a separate feed underneath answering none of them — `overview-health.tsx`, `admin-activity-feed.tsx`), the destination index (`admin-sections.tsx` over `src/lib/admin-routes.ts`), category and feature configuration (`category-management.tsx`, `category-editors.tsx`, `category-delete-action.tsx`), retention and upload limits (`platform-settings.tsx`, `retention-groups.ts`, `platform-setting-fields.ts`), people and scoped access (`people-console.tsx`, `user-management.tsx`, `user-details-dialog.tsx`, `access-management.tsx`), the record log (`audit-console.tsx`, `admin-audit-log.tsx`, where a recorded action opens in full rather than being cut off inside a column), runtime policies (`policy-settings.tsx`, `policy-history.tsx`), and the failure surface (`system-console.tsx`, whose failures, capacity and providers are three views rather than one scroll, over `system-queue.tsx`, `system-capacity.tsx`, `provider-diagnostics.tsx`). `notion-rebuild-action.tsx` confirms and queues a complete background rebuild of the Notion archive. A failure is a row that names its own refusal (`failure-row.tsx`) over the one reading of jobs, deliveries and cleanup backlog that `system-failures.ts` builds, and it opens in full in `failure-detail-sheet.tsx`; one control above the list retries everything at once. A category is a row that opens its decisions in a sheet, so the content screen does not lay every category out at once. Every retry in the product lives in `system-queue.tsx`; `apply-review-dialog.tsx` is the single before-and-after confirmation and `apply-progress.tsx` the single progress panel. Stateful reads and mutations stay in domain hooks.
- `src/components/composer-route-skeleton.tsx` — the composer routes while their own chunk is still arriving: the real layout and fields in their pending state, so nothing about the skeleton can drift from the form it stands in for.
- `src/components/composer-layout.tsx` / `composer-fields.tsx` — the frame every composer route is drawn in, and the title, guided Markdown editor, character counter, and media-attachment fields inside it. The frame keeps its card inside the page gutters at every width, and the fields split into an editor column and an attachment column once the screen is wide enough to hold both. Both take a pending state, so a composer route skeleton is these components stood down rather than a separate drawing of them that can drift from the real geometry.
- `src/components/markdown-editor.tsx` — client-only Vditor 4 WYSIWYG adapter with a touch-sized priority toolbar, localized overflow actions and built-in table row/column controls, pinned parser/icon CDN configuration, IME-safe length handling, mobile paste/drop image interception, accessibility wiring, and lifecycle cleanup. The editor contains its own inline size, so wide editor content cannot widen the composer card or the page.
- `src/components/composer-media-attachments.tsx` — independent image attachment picker, previews, deletion controls, and mobile-friendly attachment guidance kept outside the Markdown editor. Previews are the shared `ui/image-preview.tsx` tiles and open in its lightbox, so an attachment looks and opens the same way before and after it is published, and they fill whatever width the panel is given.
- `src/components/discussion.tsx`, `comments/comment-composer.tsx`, `comments/comment-thread.tsx` — shared server-sorted discussion card, fixed safe-area composer with vertically aligned 40px avatar/action geometry, focus-ring-free textarea presentation, reply-target preview, and collapsible reply-rail presentation. The dock publishes only its ResizeObserver-measured height; CSS owns safe-area clearance so visual viewport and keyboard changes cannot inflate page padding.
- `src/components/content-author.tsx` — shared author avatar and name row for list/detail content; unresolved profiles reserve a 24px avatar plus 64px mixed-script name skeleton and never flash a generic member label.
- `src/lib/render-markdown.ts` — the sanitizer for untrusted Markdown; inline images are forbidden so attachments render only through `DecodedImage`.
- `src/components/content-renderer.tsx` — Markdown/media presentation over `render-markdown.ts`; its optional field-level reveal affects Markdown text only and leaves media/card chrome outside the filter layer. Attached images are drawn with the shared `ui/image-preview.tsx` tiles and opened in its lightbox.
- `src/components/content-resolution-notice.tsx` / `content-resolution-notice-skeleton.tsx` — shared success/error conclusion block for closed proposals and facility reports, paired with a lightweight field-level skeleton shown only after the closed status is known; the resolved block uses status-aware copy and reduced-motion-safe state entrance animation.
- `src/components/detail-toolbar.tsx` — shared, geometry-stable secondary toolbar. Its back control is also where a visit that began on a shared link is asked whether Novae is already installed, because that is the moment the reader wants more than the page they were sent. Every route that primary navigation does not point at wears it, so a detail, a composer and an administration area all carry the same back control in the same place.
- `src/components/detail-actions-menu.tsx` — what else can be done to the record a detail route is showing: the overflow menu, its optional management item, and the confirmation behind its deletion, shared by proposals, facility reports and announcements.
- `src/components/protected-app.tsx`, `app-providers.tsx`, `app-update-gate.tsx`, `app-install-prompt.tsx`, `app-install/prompt-step.tsx`, `app-notification-prompt.tsx`, `app-locale-gate.tsx` — startup/session, providers, theme/i18n, transitions.dev-matched pill toast boundaries, bounded forced PWA updates with version polling and reload recovery, session-scoped proactive mobile install guidance, authenticated desktop/installed-PWA notification opt-in guidance using the current dialog system, and the local-only first-visit language gate shown until the browser has an explicitly chosen locale.
- `src/components/turnstile-provider.tsx` — Managed Cloudflare Turnstile execution for login and session verification. Signing in shows the check in place, always, because nothing may happen before it passes; restoring a session runs it silently and only raises a surface when Cloudflare asks for a person, so returning to the app no longer means answering for it. The root layout owns early script preloading and preconnecting, while tokens remain in memory and single-use at the backend boundary.
- `src/components/feature-route-guard.tsx` — shared disabled-feature guard for direct proposal and facility routes.
- `src/components/ui/route-skeleton.tsx` and route `loading.tsx` files — prefetched list and detail app-shell fallbacks that reuse the same title, permission-aware action bar, header/grid/control geometry as their resolved routes while skeletonizing only unresolved domain fields. Feed skeletons mirror each domain card's author, progress/location, status, and interaction rows; their empty states retain the same grid and card geometry while replacing data fields with the resolved message/action. Detail fallbacks do not speculate about status-dependent conclusion content, and no domain requests are started by the fallback.
- `src/components/ui/tooltip.tsx` — shared fine-pointer-only tooltip capability boundary; touch and non-hover devices keep labelled controls without opening tooltip layers.
- `src/components/ui/loading-spinner.tsx`, `action-feedback-icon.tsx`, `pending-alert-dialog-action.tsx` — shared baseline-independent loading spinner and transitions.dev-style spinner-to-check primitives for backend mutation, destructive confirmation, and update feedback.

## Hooks and stateful flows

- `src/hooks/session-store.ts` — the React-free session store: Firebase authentication, restored-session security verification, new-login-only backend profile synchronization, authoritative role/permission bootstrap, setup status, and supported-issue session state.
- `src/hooks/use-session.tsx` — the React surface over `session-store.ts`: `SessionProvider`, the `useSession` snapshot, and the permission/login/logout callbacks.
- `src/hooks/use-categories.ts` — category and platform-feature store.
- `src/hooks/use-issue-feed.ts`, `use-issue-detail.ts` — issue list/detail fetching, pagination, comments, support, and delete flows; successful deletes retain the mounted detail entity through the success hold/navigation while a shared deletion marker removes it from list snapshots, preventing a transient not-found page. Categories without comment capability short-circuit comment reads and presentation.
- `src/hooks/use-facility-feed.ts`, `use-facility-detail.ts`, `use-facility-status.ts` — facility list/detail, affected-user, delete, and moderation flows.
- `src/hooks/use-announcement-feed.ts`, `use-announcement-detail.ts` — announcement list/detail, likes, comments, and deletion.
- `src/hooks/use-notifications-page.ts`, `use-notification-badge.ts` — notification aggregation, realtime subscriptions, pagination, target routing, and unread hints.
- `src/hooks/use-route-preload.ts` — authenticated route bundle and RSC-shell warming only; primary, category, composer, and detail route shells preload immediately once their authenticated route set is known, without mounting data hooks or requesting content services.
- `src/hooks/use-intent-prefetch.ts` — one document-level listener that warms whatever a pointer or the focus ring has settled on: pressing or focusing an internal link, or resting a mouse on one, fetches that route's code and, for a detail route, the record it will show, so the click has nothing left to wait for. A hover has to stay put briefly before it counts, so a pointer crossing a list does not warm every card in it. Each destination is warmed once; a warm-up that fails is left for the page to report.
- `src/hooks/use-entry-composer.ts` — issue/facility/announcement composer workflows and upload rollback.
- `src/hooks/use-initial-setup.ts` — setup validation, persistence, polling, and retry-safe completion.
- `src/hooks/use-category-management.ts`, `use-platform-settings.ts`, `use-access-management.ts`, `use-operation-policies.ts` — category configuration, platform retention/media-limit configuration, category-scoped RBAC, and runtime policy flows. All four hold a `useDraft` and reach the backend only from its `submit`, and all four keep their last reading on screen while the fresh one arrives, so returning to a settings screen shows its values rather than a skeleton.
- `src/hooks/use-draft.ts` / `src/lib/draft-diff.ts` / `src/components/ui/save-bar.tsx` / `src/components/admin/apply-review-dialog.tsx` — the one explicit-save mechanism: an editing session over a stored value, the field-by-field difference it would write, the single control that writes it, and the confirmation that shows both the difference and the records it would disturb. The save bar and the background-work panel both arrive and leave along the edge they are pinned to, so neither appears or disappears between two frames.
- `src/hooks/share-entry-store.ts` / `use-share-entry.tsx` — whether this tab was opened from a link somebody shared, read from the URL at module load because signing in rewrites the route. A shared page shows itself and nothing else; the install conversation waits for the reader to leave it.
- `src/hooks/unsaved-changes-store.ts` / `use-unsaved-changes.tsx` — what the current screen would lose, and the guard that stops an in-app link from discarding it. The browser's own Back button is out of reach: the App Router exposes no cancellable navigation event, and faking one with a history sentinel would be worse than the gap.
- `src/lib/poll-schedule.ts` — how long to wait before looking again at work the reader just queued; it decelerates and settles instead of asking once a second forever.
- `src/hooks/use-push-token-heartbeat.ts`, `src/services/push-token-registration.ts` — authenticated-shell push-token confirmation, seven-day client throttling, shared-device token reassignment, and settings-page enable/disable registration primitives.
- `src/services/push-notifications.ts` — push permission, device token registration, and personal push preference writes; split out of `notifications.ts`, which keeps the notification feed, read state, and badge.
- `src/hooks/use-remembered-state.ts` — the reading an administration panel keeps while nobody is looking at it, held in the same view memory the feeds use and scoped to the signed-in account. Every administration panel is built on it, so leaving a screen, or moving between the views of one screen, no longer throws the reading away and asks the backend the same question again; a panel reports a cold read only when there is genuinely nothing to show.
- `src/hooks/use-admin-overview.ts` — the one reading behind `/admin`, merging the platform dashboard with the administrative activity figures. It reads the dashboard through the existing short-lived cache instead of forcing past it, and changing the reporting window re-reads only that window, the first time that window is asked for.
- `src/hooks/use-admin-console.ts` / `use-system-console.ts` — user search/restriction and audit-log flows, and the combined queue/capacity surface. Users and the audit log are one paged, searched reading over two tables rather than two copies of it. Every failed background job, deletion included, is one row in one panel with one retry behind it, and that retry removes the row it belongs to rather than re-reading the whole console.
- `src/hooks/use-permission-redirect.ts` — shared client-side redirect for authenticated routes that require a specific permission.
- `src/hooks/use-push-notifications.ts`, `use-pwa-install.ts`, `use-app-install-prompt.ts`, `use-app-notification-prompt.ts` — device push preferences, explicit install actions, the standalone-aware automatic install prompt flow, and a session-scoped notification prompt for authenticated desktop or installed-PWA sessions whose browser permission remains undecided; mobile web notification enablement continues through installation guidance, while settings present each push write through the shared targeted spinner-to-check lifecycle.
- `src/hooks/use-image-attachments.ts`, `use-resolved-markdown.ts`, `use-public-profiles.ts`, `use-cold-data-reveal.ts` — reusable media, Markdown, synchronous public-profile memory hydration, and cold-read display state helpers. Resolved content replaces its loading presentation in the same render cycle.
