# Novae repository structure

This document is the maintained map of the repository. Read it before broad searches and update it whenever files or responsibilities move.

## Runtime and entry points

- `package.json` / `bun.lock` — Bun 1.4 package management with a pinned install graph; Node 24 remains the Vite, build-script, and Worker runtime alongside Vite 8, React Router 8, React 19.2, TypeScript 7, Tailwind CSS 4, Radix/shadcn primitives, Motion, Vditor 4 WYSIWYG Markdown editing, Serwist, Vitest, and Playwright.
- `index.html` — the one document: metadata, stable immersive iOS viewport/status-bar configuration, manifest and icons, and the `<!-- novae:boot -->` slot the build fills with the boot script (plus Turnstile preconnect when a site key is set).
- `src/app/main.tsx` — entry: loads the HarmonyOS Sans TC split font, the self-hosted Inter/Roboto Mono (`src/assets/fonts/`) and global CSS, creates the router, binds it to `src/lib/app-navigation.ts`, and registers the service worker in production.
- `src/app/routes.tsx` — every address as a React Router lazy route, each screen its own chunk and administration a chunk family of its own; root error boundary that reloads once into a new deployment when a chunk is gone; the route progress line.
- `src/app/document-policy.ts` — the fixed boot script (theme before paint, then the entry named in `<meta name="novae-entry">`), the Content-Security-Policy that trusts it by hash under `'strict-dynamic'`, and the other document headers. `vercel.json` must carry the same policy; the build checks it.
- `src/app/web-manifest.ts` — the web app manifest, written to `manifest.webmanifest` at build time.
- `src/app/globals.css` — imports the HarmonyOS font, Tailwind, the generated motion ladder and `src/ui/theme.css`/`motion.css`; defines the font stacks, page-level touch, selection and scrollbar policy, and the `.markdown-body` styles.
- `src/assets/fonts/harmonyos-sans-tc/` — generated, project-character-scoped HarmonyOS Sans TC Regular, Medium, Semibold, and Bold shards plus CSS; refreshed by `scripts/generate-harmonyos-subset.mjs`.
- `src/features/content/markdown-editor.css` — scoped Vditor toolbar, WYSIWYG content, focus, mobile keyboard, reduced-motion and loading overrides on the dark tokens; wide tables scroll inside the bounded editor.
- `config/build-budget.config.json` / `scripts/check-build-budget.mjs` / `scripts/build-budget-metrics.mjs` — route-specific first-load JS, raw UI CSS and gzip estimates from the Vite manifest, separate font declarations, CSS chunk limits, and existing font/JS inventory limits. Writes a build-local report; see `docs/testing.md` for maintenance.
- `src/app/sw.ts` — Serwist service worker; `@serwist/vite` compiles it to `dist/sw.js` with an `index.html` navigation fallback, while WOFF2 font shards stay outside install-time precaching and load normally through their unicode ranges. `src/lib/service-worker.ts` registers it.
- `vite.config.ts` — public `NEXT_PUBLIC_*` environment written into the bundle, build-time `version.json` and manifest, the boot-script loader and its CSP check, vendor chunk groups, Serwist, and preview headers. Output goes to `dist/` (or `NOVAE_DIST_DIR`).
- `public/` — brand identity assets (`logo.svg`, `logo.png`, `favicon.ico`, `apple-touch-icon-180x180.png`, `maskable-icon-512x512.png`, `pwa-*.png`) and static images, copied into `dist/` as they are.
- `vercel.json` — Vercel static (Vite) build with an explicit frozen Bun install command, the SPA rewrite to `index.html`, the fixed security headers, and cache rules (immutable `/assets/`, no-cache document, `sw.js`, `version.json`).

## Routes

- `/login` — focused Google sign-in presentation with the website's blue brand statement and desktop constellation image; the mobile authentication path stays compact.
- `config/brand.svg` / `scripts/generate-brand-assets.mjs` — vector N speech mark and reproducible logo, favicon, and PWA icon generation.
- `src/features/auth/login-page.tsx` — the sign-in screen, loaded by the `/login` route.
- `src/hooks/use-login-entrance.ts` — login preparation, immediate pending state, and in-place verification retry.
- `src/hooks/use-comment-feed.ts` — shared discussion sorting, pagination, read errors and request generations; late responses cannot replace newer selections.
- `src/features/shell/protected-app.tsx` — authenticated application guard around every signed-in route. Each route's outlet is placed by `src/features/shell/app-views.tsx`, which pins the list a record opens over so it keeps its screen, scroll and state underneath the sheet. Record and composer addresses (`/issues/[filter]/[id]`, `/issues/[filter]/compose/new`, `/facilities/[id]`, `/facilities/new`, `/announcements/[id]`, `/announcements/new`) load directly and stay shareable; old list addresses (`/issues`, `/issues/[filter]`, `/facilities`, `/announcements`) forward to `/feed`.
- `/setup` — admin-only idempotent category setup with completion recovery in `use-initial-setup`; first-visit language selection happens through the shared locale gate before any route.
- `src/lib/route-hierarchy.ts` — the in-app route table (`matchAppRoute`), which addresses open over a list, the primary destination each belongs to, and where the dock steps aside. `src/lib/app-navigation.ts` changes the address in place (`navigate`, `pushAddress`) and marks entries reached from inside the app, so a record knows whether Back returns to its list; `src/ui/app-link.tsx` is the link that uses it, and `src/hooks/use-app-location.tsx` gives each screen the address it is drawn for (`useAppLocation`, `useRecordId`, `useAppNavigate`). Administration is `/admin` plus one address per section in `src/lib/admin-routes.ts`; `src/features/admin/shell/admin-layout.tsx` mounts `AdminShell` once around whichever section route is open.

## Presentation components

- `src/ui/` — business-free primitives (`DESIGN.md` is their contract): `theme.css` tokens and the `glass` material, `motion.css` skeleton recipe, the enter/exit animation of floating surfaces, content, message and bar arrivals, and the route progress line, `button`, `chip`, `panel`, `list`/`list-controls`, `segmented`, `select`, `menu`, `popover`/`Tooltip`, `sheet` (rises from the bottom on phones on the iOS curve and is pulled away by its grabber, a centred panel from `md`; `layout="record"` fills a phone screen; `onClosed` fires after its exit), `app-link`, `dialog`/`confirm-dialog`, `decision` (`DecisionSheet`), `save-bar`, `page` (`PageHeader`, empty/error/loading states), `nav` (`PrimaryNav` dock and rail), `image` (`DecodedImage`, tiles, lightbox) over `use-decoded-image.ts`, `avatar`, `feedback`, `animated-number`. They import no hooks or services.
- `src/features/shell/` — `app-providers.tsx` (Motion, tooltip, Turnstile and session providers; i18n gate; update, install and e2e bridges; toaster), `protected-app.tsx` (session/setup redirects behind a startup overlay that fades out), `app-views.tsx` (the view host: every signed-in screen, with records and composers as sheets over the screen beneath, which stays pinned to its own address), `app-shell.tsx` (glass sidebar with the account menu and `PrimaryNav` rail from `md`; floating dock on phones, hidden where `route-hierarchy.ts` says so; a blurred fade where content scrolls under the bottom edge), `startup-screen.tsx`, `locale-gate.tsx`, `brand.tsx`.
- `src/features/system/` — `update-gate.tsx` over `use-app-update.ts`, `install-prompt.tsx`, `notification-prompt.tsx`, `e2e-auth-bridge.tsx`. `src/features/security/turnstile.tsx` — Managed Turnstile provider and widget.
- `src/features/auth/login-page.tsx`, `src/features/setup/` — sign-in, and first-run category setup with its draft editors.
- `src/features/content/` — what the three record domains share. `record-frame.tsx` frames a record or composer as `RecordSheet` over its list, opened and closed by the address; closing steps back through history when the list is behind it and otherwise replaces the address with the list, and `useRecordFrame()` exposes `close` and `listHref`. `feature-guard.tsx` hides a domain that is switched off. `record-view.tsx` (header, share/manage/delete actions, skeleton, error), `markdown.tsx` over `render-markdown.ts`, `markdown-editor.tsx`/`.css` (Vditor), `composer.tsx` (title, body, images, draft notice, submit), `attachments.tsx`, `discussion.tsx` with `comment-thread.tsx`/`comment-composer.tsx`, `reaction.tsx`, `resolution-notice.tsx`, `person.tsx`, `status.tsx` (status chip, tone and colour).
- `src/features/feed/` — `feed-page.tsx`, the `/feed` hub: a view pill for proposals, announcements and facility reports plus a category select, all URL-backed through `use-feed-url-state.ts` and `src/lib/feed-href.ts`; `feed-list.tsx`, `feed-controls.tsx` (search popover, sort), `record-card.tsx`.
- `src/features/issues/`, `facilities/`, `announcements/` — each domain's card, feed section, detail and composer; issues add `issue-panels.tsx` (support progress, supporters, timeline) and `moderation-sheet.tsx`, facilities `facility-status-sheet.tsx`, announcements the unread `announcement-notice.tsx` pill.
- `src/features/home/`, `notifications/`, `settings/` — the home start panel, destination cards and per-domain status bars; the notification list; the profile header and grouped settings.
- `src/features/admin/` — the administration area by section (`shell`, `shared`, `overview`, `people`, `content`, `policies`, `platform`, `system`, `audit`). `shell/admin-shell.tsx` owns permission redirects, the section nav, `apply-progress.tsx` and the unsaved-changes guard; `shared/review-dialog.tsx` and `draft-bar.tsx` are the one confirm-and-save path over `use-draft.ts`.

- `src/lib/markdown-editor-value.ts` normalizes Vditor's synthetic final line break before draft persistence and controlled value comparison; editor value tests preserve multiline structure. `AppUpdateGate` releases failed version-check leases so reconnecting can retry promptly.

- `src/hooks/use-foreground-poll.ts` shares visibility/online-aware, sequential exponential polling between setup and administration. Invalidation bursts need no scheduler of their own: `src/lib/query-client.ts` marks queries stale and refetches only the active ones while the tab is visible.
- `src/hooks/use-feed-url-state.ts` and `src/lib/feed-url-state.ts` validate URL-backed feed filters and use native history without a server navigation per keystroke. `use-discussion-composer.ts` scopes comment/reply drafts and preserves edits across submission completion. `use-update-deferral.ts` guards PWA reloads while editing or offline.
- `src/services/realtime-tab-coordinator.ts` elects a per-account/role Web Lock owner and relays credential-free events with BroadcastChannel; `realtime-transport.ts` owns the socket, generation fencing, fallback and foreground resynchronization.

- `src/services/notifications.ts` pages the inbox with the contract's `NotificationCursor`; forward migrations `0048` and `0049` correct inbox cursors, expiry filtering and monotonic read watermarks. `use-notifications-page.ts` reads through `useInfiniteQuery`, so an old response only writes its own query key and cannot overwrite a refreshed inbox.

- `src/services/upload-delivery.ts` — account-scoped public image references, memory-only private URLs, inherited-access invalidation, bounded resolution batches and expired lightbox renewal. `uploads.ts` owns the upload lifecycle.
- `src/lib/route-hierarchy.ts` — which primary destination a route belongs to (records and composers to the feed, administration to settings), whether a route is one shareable record, and where the phone dock steps aside.
- `src/lib/share.ts` — shares the current page, marking the link so the tab it is opened in knows it arrived from somebody else. Inside a messaging app's browser the marker is written into the address instead of removed, so the handoff carries it whether it goes through Novae or through the app's own menu; nothing arrives in one of those browsers except through a link somebody sent. Links shared before the marker existed are recognised by shape instead: a tab with no history of its own that opened straight onto one piece of content.
- `src/lib/avatar-cache.ts` — the avatar this browser was last given, kept for the day the worker would answer from its own copy anyway, so opening Novae again is not a rate-limited write.
- `src/lib/render-markdown.ts` — the sanitizer for untrusted Markdown; inline images are forbidden so attachments render only through `DecodedImage`.

## Hooks and stateful flows

- `src/hooks/session-store.ts` — the React-free session store: Firebase authentication, restored-session security verification, new-login-only backend profile synchronization, authoritative role/permission bootstrap, setup status, and opening or forgetting the account's query cache.
- `src/hooks/use-session.tsx` — the React surface over `session-store.ts`: `SessionProvider`, the `useSession` snapshot, and the permission/login/logout callbacks.
- `src/hooks/use-categories.ts` — category and platform-feature store.
- `src/hooks/use-issue-feed.ts`, `use-issue-detail.ts` — issue list/detail fetching, pagination, comments, support, and delete flows; successful deletes retain the mounted detail entity until navigation finishes while a shared deletion marker removes it from list snapshots, preventing a transient not-found page. Categories without comment capability short-circuit comment reads and presentation.
- `src/hooks/use-optimistic-reaction.ts` shares per-record locking, immediate reaction feedback, confirmation and rollback across all three content domains. The server's answer settles every cached copy of the record through `patchEntity`.
- `src/hooks/use-action-feedback.ts` shares concurrent calls to one operation and retains a success indicator without holding up the returned result. Its timer is cleared before another operation or unmount.
- `src/hooks/use-facility-feed.ts`, `use-facility-detail.ts`, `use-facility-status.ts` — facility list/detail, affected-user, delete, and moderation flows.
- `src/hooks/use-announcement-feed.ts`, `use-announcement-detail.ts`, `use-announcement-notice.ts` — announcement list/detail, likes, comments, deletion, and the account-synchronized notice that refreshes after offline or realtime recovery.
- `src/hooks/use-notifications-page.ts`, `use-notification-badge.ts` — notification aggregation, realtime subscriptions, pagination, and unread hints. The notification page renders valid targets as non-prefetched record links, so they share immediate sheet feedback with feed links; removed records remain a labelled button with an informational message.
- `src/hooks/use-entry-composer.ts` — issue/facility/announcement composer workflows and upload rollback.
- `src/hooks/use-initial-setup.ts` — setup validation, persistence, polling, and retry-safe completion.
- `src/hooks/use-category-management.ts`, `use-platform-settings.ts`, `use-access-management.ts`, `use-operation-policies.ts` — category configuration, platform retention/media-limit configuration, category-scoped RBAC, and runtime policy flows. All four hold a `useDraft` and reach the backend only from its `submit`, and all four keep their last reading on screen while the fresh one arrives, so returning to a settings screen shows its values rather than a skeleton.
- `src/hooks/use-draft.ts` / `src/lib/draft-diff.ts` / `src/ui/save-bar.tsx` / `src/features/admin/shared/review-dialog.tsx` — the one explicit-save mechanism: an editing session over a stored value, the field-by-field difference it would write, the single control that writes it, and the confirmation that shows both the difference and the records it would disturb. The save bar and the background-work panel both arrive and leave along the edge they are pinned to, so neither appears or disappears between two frames.
- `src/hooks/share-entry-store.ts` / `use-share-entry.tsx` — whether this tab was opened from a link somebody shared, read from the URL at module load because signing in rewrites the route. A shared page shows itself and nothing else; the install conversation waits for the reader to leave it.
- `src/hooks/unsaved-changes-store.ts` / `use-unsaved-changes.tsx` — what the current screen would lose, and the guard that stops an in-app link from discarding it. The browser's own Back button is not intercepted; the guard covers in-app links.
- `src/lib/poll-schedule.ts` — how long to wait before looking again at work the reader just queued; it decelerates and settles instead of asking once a second forever.
- `src/hooks/use-push-token-heartbeat.ts`, `src/services/push-token-registration.ts` — authenticated-shell push-token confirmation, seven-day client throttling, shared-device token reassignment, and one-way settings-page enablement.
- `src/services/push-notifications.ts` — push permission, device token registration, and platform-admin notification preference reads/writes; split out of `notifications.ts`, which keeps the notification feed, read state, and badge.
- `src/hooks/use-remembered-state.ts` — the reading an administration panel keeps while nobody is looking at it, held in the query cache the feeds use. Every administration panel is built on it, so leaving a screen, or moving between the views of one screen, no longer throws the reading away and asks the backend the same question again; a panel reports a cold read only when there is genuinely nothing to show.
- `src/hooks/use-admin-overview.ts` — the one reading behind `/admin`, merging the platform dashboard with the administrative activity figures. It reads the dashboard through the existing short-lived cache instead of forcing past it, and changing the reporting window re-reads only that window, the first time that window is asked for.
- `src/hooks/use-admin-console.ts` / `use-system-console.ts` — user search/restriction and audit-log flows, and the combined queue/capacity surface. Users and the audit log are one paged, searched reading over two tables rather than two copies of it. Every failed background job, deletion included, is one row in one panel with one retry behind it, and that retry removes the row it belongs to rather than re-reading the whole console.
- `src/hooks/use-permission-redirect.ts` — shared client-side redirect for authenticated routes that require a specific permission.
- `src/hooks/use-push-notifications.ts`, `use-pwa-install.ts`, `use-app-install-prompt.ts`, `use-app-notification-prompt.ts` — device push preferences, explicit install actions, the standalone-aware automatic install prompt flow, and a session-scoped notification prompt for authenticated desktop or installed-PWA sessions whose browser permission remains undecided; mobile web notification enablement continues through installation guidance, while settings present each push write through the shared targeted spinner-to-check lifecycle.
- `src/hooks/use-image-attachments.ts`, `use-resolved-markdown.ts`, `use-public-profiles.ts` — reusable media, Markdown and public-profile reads. Resolved content replaces its loading presentation in the same render cycle.
- `src/hooks/use-content-realtime.ts`, `use-action-feedback.ts` — deployment-configurable route-scoped content realtime lifecycle, and 500 ms successful-action feedback lifecycle.

## Data, domain, and infrastructure

- `shared/operation-policies.ts` / `shared/rate-limits.ts` / `shared/data-retention.ts` — operational policy bounds, business quotas and retention defaults, imported directly by the frontend and the Worker; quota defaults come from `RATE_LIMITS`.
- `cloudflare/src/backend/shared/operation-policies.ts` — the one way runtime policies are read and the one way they are reached: an entry point enters `withOperationPolicies` and everything under it asks `operationPolicy(key)`, rather than a value threaded through every call. An isolate re-reads the stored settings at most once a minute; the console that edits them reads afresh and forgets that cache when it saves.
- `cloudflare/src/backend/shared/operational-telemetry.ts` — bounded daily error aggregation without request bodies or credentials.
- `cloudflare/src/backend/shared/provider-diagnostics.ts` / `src/hooks/use-provider-diagnostics.ts` / `src/lib/provider-diagnostics-format.ts` / `src/features/admin/system/provider-diagnostics.tsx` / `provider-readings.tsx` — administrator-only provider diagnostics using server-side credentials, with explicit unavailable and unconfigured states. Each provider answers in its own dialect, so the reply is read into named figures and shown as the same rows the rest of administration uses; the response it arrived in stays one row away, in a sheet, for the questions the figures do not answer. The two providers that report standing figures are read as the panel opens; the log stream is a search and waits to be asked.
- `cloudflare/src/backend/actions/operations.ts` — platform-admin capacity, job, delivery, policy and policy-history management.
- `src/lib/operation-policies.ts` / `src/services/operations-console.ts` / `src/hooks/use-operation-policies.ts` / `src/features/admin/policies/policy-console.tsx` — runtime client policies, edited as a draft with a required reason and an audited revision history. The client holds the revision it was last given; every successful response names the revision it was produced under, so a change is noticed from traffic the page was making anyway and costs one request, and a client that is asking for nothing asks for nothing.
- `database/migrations/0022_runtime_operations.sql` — revisioned operations settings, audited changes, daily error aggregates and capacity samples.
- `database/migrations/0060_admin_queue_indexes.sql` / `scripts/verify-admin-performance.mjs` — console ordering indexes and a reproducible isolated 50,000-row benchmark. `0061_avatar_delivery_cache_policy.sql` adds avatar cache lifetimes while preserving existing policies.

- `src/services/` — frontend boundary for the Cloudflare Workers API, activity-aware native WebSocket realtime transport, uploads, Firebase-backed sessions, backend actions, and the session-seeded runtime push-confirmation interval. Every API operation creates one UUID sent as `X-Novae-Operation-Id`; request/response cursors use camelCase UTC ISO timestamps. Realtime closes after 30 idle minutes, suppresses reconnects until activity or foreground return, then deduplicates subscriber resync; `realtime-heartbeat.ts` pings the open connection so it is neither dropped in silence nor left waiting on a socket that has already died. Every verified Firebase session synchronizes its backend profile and reconciles `ADMIN_EMAILS` before access bootstrap; Firebase token validation warms during Turnstile execution but is consumed only after unchanged Siteverify succeeds. Every browser API request obtains an App Check token through the shared security helper, and no browser database client exists.
- `src/services/announcement-notice.ts` — the small frontend boundary for the account-scoped announcement unread probe and bounded mark-through write; announcement content reads and mutations remain in `announcements.ts`.
- `src/lib/motion-timing.ts` — the one way an animation driven from JavaScript names a duration or a curve; it hands back rungs of the generated ladder so Motion and the stylesheet stay in step.
- `src/lib/` — framework-independent request, Firebase/App Check, Google identity, in-app browser and PWA-install contracts, the query cache, Markdown, image, route, formatting, pagination, and active domain utilities. `vditor-i18n.ts` maps the localized application catalog to Vditor's toolbar contract. Obsolete Vue-era route-name, touch interception, caret/table editor, and `motion-v` compatibility helpers are intentionally removed rather than excluded from checks.
- `src/lib/backend-security.ts` — shared Firebase ID token plus App Check request-header construction for browser-to-Worker API calls.
- `src/lib/request.ts` — shared timeout and cancellation boundary for browser requests; already-aborted parents short-circuit before an operation can start, while active aborts and deadlines reject even if the underlying operation ignores its signal.
- `src/lib/abort-signal.ts` — shared abort-aware async race that rejects pre-aborted work immediately and removes listeners after settlement.

- `src/hooks/use-paged-query.ts` — one list read a page at a time on the query cache, for feeds and discussions alike; duplicate page requests share one fetch and a refresh supersedes an older page.
- `src/lib/query-client.ts` — the one query client: content-domain invalidation, `patchEntity`/`dropEntity` over every cached copy of a record, and the per-account IndexedDB record restored before the first screen and deleted with the session.
- `src/lib/reaction-state.ts` — shared pure optimistic reaction state transition used by proposal support, facility affected, and announcement like flows so immediate counts and rollback snapshots follow one rule.
- `src/lib/feed-page-limit.ts` — runtime-configured retained-page ceiling for content and notification feeds so long browsing sessions keep bounded React state and DOM size.
- `src/lib/category-management-state.ts` — pure category-draft construction, identity validation, and default-preserving removal used by the management hook.
- `src/lib/platform-job-events.ts` — tiny same-tab refresh signal shared by settings mutations and the observable background-job panel.
- `src/lib/notification-target.ts` — pure direct notification-to-route resolution used for immediate navigation without a preliminary content fetch.
- `src/lib/ndjson.ts` — newline-delimited JSON read off a response as it arrives, holding back a line until the newline that completes it.
- `src/lib/realtime-timing.ts` — the two clocks the realtime transport runs on: the inactivity window that bounds an idle WebSocket's lifetime, and the heartbeat interval that keeps a live one from being dropped in silence.
- `src/constants/share.ts` — the mark a shared link carries and the routes that earn it, named where both the share and the handoff out of an in-app browser can reach them. Only a single piece of content counts: someone handed the front door or a feed is meeting Novae for the first time and is still invited to install it.
- `src/constants/admin-activity.ts` — the periods the administration overview reports on and the four figures a period is read as, named once for the overview, the figure's own screen, and the full activity record.
- `src/constants/` — generated/static application, account-access presets, category, status, retention, API error, and rate-limit constants.
- `src/types/` — shared frontend/domain types.
- `src/i18n/` — reactive React i18n store and paired `en` / `zh-TW` domain catalogs. `ui.ts` contains the rebuilt interface language; only explicit user choices persist the locale locally.
- `src/generated/` — generated frontend contracts; do not edit manually. `motion-ladder.css` and `motion-tokens.ts` are the two halves of the same motion ladder, so a stylesheet recipe and a Motion transition cannot drift apart.
- `cloudflare/src/index.ts` — sole public API entrypoint for actions, App Check and Firebase auth ingress, auth sync, realtime tickets/WebSockets, signed media, Cloudinary webhooks, Queue consumption, and scheduled maintenance. The Firebase ID token is verified exactly once here and the resulting user is handed to the action, sync and realtime-ticket paths; a Queue batch collapses into one sweep because every message asks for the same bounded work.
- `cloudflare/src/app-check.ts` / `turnstile.ts` — Worker-side Firebase App Check JWT validation and Cloudflare Turnstile Siteverify boundaries; App Check is required for browser API requests and Turnstile gates first-time profile creation.
- `cloudflare/src/backend/actions/` — generated-registry-driven action dispatch and domain workflows. Authorization is enforced here and in database functions, never by frontend visibility checks. An answer leaves as newline-delimited JSON: `response.ts` writes the `start`/`part`/`end` lines, `execution.ts` turns an action's return value into the pieces they carry, and the first piece is produced before the response exists so an outright failure is still an ordinary error response with its own status.
- `cloudflare/src/backend/actions/segments.ts` — several independent reads sent in the order they come back, which is how an action whose answer is assembled from reads that do not need each other stops waiting for the slowest one.
- `cloudflare/src/backend/actions/category-catalog.ts` — the categories as every other action reads them: the runtime category shapes, the policy lists derived from them, and the catalog a session is bootstrapped with. `categories.ts` keeps the admin side that rewrites them.
- `cloudflare/src/backend/actions/upload-delivery.ts` — inherited image access and signed delivery URLs, resolved in batches by target kind.
- `cloudflare/src/backend/actions/uploads.ts` dispatches the public upload actions. `upload-sessions.ts` owns bulk reservation, provider verification and transactional cleanup; `upload-markdown.ts` owns locked attachment validation. `shared/image-upload-validation.ts` keeps upload limits consistent with the signed provider webhook. Failed batches settle all pending work before rollback and cleanup; late provider notifications also clean up orphaned Novae assets.
- `cloudflare/src/backend/database/` — the PostgreSQL connection, multi-statement transaction support (`transaction(async (tx) => ...)`), the `sql`/`sqlOne`/`sqlMaybe` tagged template every statement is written in (each interpolation becomes a bound parameter), the typed `call()` into `app_api`, and generated table/RPC contracts introspected from the fully migrated PostgreSQL schema. `Row<T>` and `Selected<T, columns>` name what a statement returns, so a column a migration renames fails the build where it is read.
- `cloudflare/src/backend/events/domain-events.ts` — the event vocabulary, the finished write the domains read, and the dispatch to `issue-events.ts`, `facility-events.ts`, `announcement-events.ts` and `platform-events.ts`. An action no domain claims fails here rather than going out silently.
- `cloudflare/src/backend/events/{issue,facility,announcement,platform}-events.ts` — what one write announces, per domain: the event and the channels it is delivered to (`notion`, `in_app`, `push`, `realtime`), recorded atomically within the write transaction.
- `cloudflare/src/backend/shared/notion-*.ts` — the Notion archive in one piece each: `notion-api.ts` is the HTTP boundary, the schema it grows and the pacing that keeps a rebuild from being refused for going too fast, `notion-timeline.ts` writes the entries a page is missing — the page read once, everything missing appended a hundred blocks at a time, so a proposal with a long discussion costs a handful of requests instead of more than a Worker invocation is allowed to make, `notion-page.ts` the page a piece of Novae has and the vocabulary it is written in, `notion-event.ts` the event a delivery hands over, `notion-sync.ts` dispatches content to its domain writer, `notion-audit-events.ts` turns every administrator write into one Chinese system-operation page, and `notion-reconcile.ts` rebuilds current proposals, facilities, announcements, surviving comments, and operations from PostgreSQL a bounded pass at a time — bounded by what the whole Worker invocation has spent of its request allowance rather than by the pages a pass writes — and only writes: pages already in the workspace are the administrator's to remove. The queues a rebuild supersedes are cleared by the `rebuildNotionArchive` action when it is asked for, not when the job runs, so the operations screen stops reporting them immediately.
- `cloudflare/src/backend/jobs/` — event delivery by destination (`notion-deliveries.ts`, `notification-deliveries.ts`, `realtime-deliveries.ts`) over the shared claim-and-settle of `delivery-attempt.ts`, with what a notification says in `notification-content.ts` and who hears it in `delivery-recipients.ts`; background job execution (`background-jobs.ts`) and consumer orchestration (`consumer.ts`) driven by Cloudflare Queues, replacing legacy separate outbox, deletion, and realtime processors. A sweep asks `app_api.pending_delivery_destinations()` once and claims only for the destinations that have work, so an empty drain costs one round trip instead of five.
- `cloudflare/src/backend/shared/` — Worker environment, Firebase token validation, account access rule resolution, Cloudinary, FCM, idempotent Notion sync with timeline markers and pagination, HTTP, media, platform runtime settings, and structured observability with version 2 correlation schema.
- `cloudflare/src/durable/` — SQLite-backed business rate limits and WebSocket Hibernation realtime hub, whose heartbeat is answered by the runtime's own auto-response so a ping never wakes the object. Realtime state can reconnect from PostgreSQL content versions instead of becoming a source of record.
- `cloudflare/src/rate-limit.ts` / `cloudflare/src/media.ts` — opaque per-UID native limiter keys, invalid-auth IP breakers, and viewer-scoped media limiter keys; the Turnstile-protected login ingress permits a 300-request/minute shared-network burst before its IP breaker, while authenticated traffic is limited per UID instead of penalizing valid school traffic behind one public IP.
- `cloudflare/wrangler.json` — local/default Worker bindings for Hyperdrive, Queue, Durable Objects, cron, native rate limits, observability, and Smart Placement; deployment renders an ignored environment-specific copy.
- `database/migrations/` — fresh PostgreSQL 17 baseline and append-only migrations for Neon. `0002` bootstraps roles, `0003` completes realtime batches, `0004` seals the Worker-only database boundary, `0005` exposes scheduled support expiry, `0006` adds runtime settings, `0007` adds admin overview, user interaction restrictions, and audit-log data/functions, `0008` aligns admin user/activity visibility and adds audit-log retention cleanup, `0009` applies the complete retention lifecycle, `0010` adds permanent Notion activity archives, `0011` seeds content versions from migration time, `0012` adds permission-checked failed Cloudinary deletion recovery without exposing or changing Notion data, `0013` adds observable bounded platform policy jobs, `0014` moves the full retention surface into runtime settings plus bounded retention batches, `0015` aligns runtime retention and cleans orphaned Notion mappings, the forward `0015_z` bridge quiesces legacy projection triggers and `0015_zz` creates the no-login runtime role shell before populated or fresh clusters enter `0016`, and `0016` establishes system data consistency with atomic operations, domain events, unified event deliveries, background jobs, aggregate revisions, canonical operation/delivery/job retention keys, non-negative counter invariants, deduplicated Notion mapping, and complete retirement of legacy outbox, idempotency, and deletion tables, `0017` scopes review-queue visibility, `0018` carries per-status category counts on first list pages, and `0019` widens feed search from the title to the body and the author's display name, with the author matched only where the category shows it.
- `database/seed.local.sql` / `seed.integration.sql` — deterministic sample and backend-test seeds; production deploys never run either seed.
- `config/` — the motion ladder source, the build budget, and the brand mark. Contracts, limits, and retention live in `shared/`.
