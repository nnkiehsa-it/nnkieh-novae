# Novae UI 識別度評估

評估日期：2026-10-05。以實際執行的首頁、提案列表、詳細 sheet、附議者 sheet、設定與空白狀態為依據；檢視手機 390 × 844、桌面 1440 × 900，以及深淺色。這是設計方向評估，以下建議尚未全部實作。

## 保留的核心

首頁的書本、紙飛機與笑臉，讓「關心校園、把想法提出來」有具體而溫暖的形象。維持現有 `home-start.webp`、藍色強調色、HarmonyOS Sans、圓角表面，以及黑色 AMOLED 背景。識別度從插畫語言與內容回饋累積，不需要重做導覽或讓每張卡片增加裝飾。

## 畫面觀察

1. **首頁**：文字與小幅插畫彼此呼應，入口與近況清楚。它目前最能表達 Novae 的性格，適合作為其他畫面的參照。
2. **列表與詳細內容**：圓角、字級與藍色選取狀態一致，但品牌主要靠通用元件表達。資料閱讀應維持安靜，可把少量插畫放在頁首或狀態切換的終點。
3. **空白狀態**：目前是一般圖示、說明與按鈕，最適合加入手繪的溫度。已結案篩選沒有結果時卻顯示「建立第一個提案」，下一步也需要依情境調整。
4. **設定與附議者 sheet**：分組清楚，不需要每一組加入插畫。頁首、導覽層次和觸控回饋一致，比增加裝飾更有價值。

## 建議順序

| 優先 | 場景 | 建議 | 保留的限制 |
| --- | --- | --- | --- |
| 1 | 沒有提案、沒有通知、搜尋無結果 | 建立同一畫風的三至四張小插畫，搭配一句情境化說明與有用的下一步 | 區分「尚未有人提出」與「篩選後沒有結果」；已結案無結果優先引導回進行中或清除條件 |
| 2 | 提案送出、附議成功、設備回報完成 | 用紙飛機、手掌或小勾號的短暫回饋呼應首頁，文案直接說明結果 | 不延遲導航、不阻擋下一個操作、不用常駐動畫 |
| 3 | 提案、設備、公告頁首 | 每個領域有一個小幅手繪主題，重用相同線條粗細、留白與尺寸 | 正常列表仍以內容為主，頁首插畫不擠壓搜尋、排序與分類 |
| 4 | 詳細頁時間軸與進度 | 加強「大家的想法如何被回應」的節點文案與層次，重要完成狀態可有小幅插畫 | 狀態顏色維持原語意；不以圖樣取代數字、時間或處理結果 |
| 5 | 設定與管理工具 | 統一標題、分組間距、sheet 操作位置；產品頁首可少量延伸插畫 | 管理表單與密集資料繼續使用清楚的標準圖示 |

## 實作方式

先完成空白狀態與成功回饋這兩個可重用入口，再擴到領域頁首。插畫沿用首頁原始畫風，功能圖示保留 Lucide，避免把兩者混成同一套操作符號。深色插畫使用透明背景與合適的線色，背景仍保持純黑。

在 `FeedList` 的狀態層共用空白狀態元件；在既有送出與樂觀回饋流程中接入成功表現。裝飾圖片標記為 `aria-hidden`，真正的狀態保留文字。每一批都檢查窄螢幕、兩種主題、減少動態效果與實際長文字。

本批已實作的範圍是卡片上下 padding 各增加 4px，以及移除 sheet 底部固定空白帶；沒有更動上述尚待評估的插畫與資訊層次。

## 證據限制

本次在受控 Chromium 瀏覽器檢視畫面；底部 inset 另由既有瀏覽器測試模擬 34px 驗證。實機 iOS 的 Home Indicator、Safari 工具列和觸控體感仍需要手機驗收。
