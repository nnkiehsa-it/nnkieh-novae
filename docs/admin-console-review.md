# 管理面板檢查與整理

範圍包含每個管理操作與所有設定，介面採用「分類摘要 → 選定區域 → 編輯」；保留 Novae 現有的字體、圓角、列表與手機操作方式。此文件記錄檢查範圍，不代表未列出證據的項目已驗證。

| 區域 | 操作與設定範圍 | 必須核對的結果 |
| --- | --- | --- |
| 總覽 | 期間、刷新、統計、健康狀態、管理入口 | 期間與網址一致，未載入不顯示為零或健康，舊讀取不覆蓋新期間 |
| 內容與分類 | 提案、設備、公告，功能開關、分類增刪、預設分類、讀取與作者政策、附議、留言、圖片、作者刪除、範本與重置 | 草稿與正式值分開；前後端範圍一致；既有分類的隱私設定固定；分類版本、實際影響與背景套用結果正確 |
| 平台設定 | 內容、隱私、運行紀錄、稽核、上傳保留，圖片尺寸、檔案大小與品質，整體保留檔位、圖片檔位與各區還原 | 只處理變更範圍；確認分清刪除、期限更新與未來資料；整體保留檔位明確包含清理開關；成功回應為正式值 |
| 帳號與權限 | 搜尋、分頁、個別限制、前綴規則、公告與各分類負責成員，新增與撤銷 | 管理員身分來自正式名單；期限、優先順序、人數、成員版本、交易與回傳狀態一致 |
| 運行政策 | 內容限制、操作頻率、用戶端、批次工作、紀錄、即時更新，檔位、單欄重置、區域還原、原因與歷史 | 所有欄位符合生成契約；檔位不越界；原因與修改一起保存；版本衝突保留草稿 |
| 系統運作 | 佇列刷新、分頁、單項與全部重試、清除錯誤、清除排程、重建 Notion、容量、外部服務 | 清楚區分讀取與寫入；顯示實際處理數與狀態；禁止重複送出；刷新失敗不誤報寫入失敗 |
| 稽核紀錄 | 搜尋、分頁、展開詳情、活動期間與游標 | 實際欄位值、空值、動作、帳號與操作關聯完整，讀取錯誤與空清單分開 |

## 共用檢查

- 各類設定的共用流程核對儲存、取消、重置、非法值、版本衝突與失敗後的草稿。
- 新增、修改、刪除與重試的確認內容須對應本次送出的資料。
- 未儲存變更在切換分類、返回與換頁時仍可辨識，成功後才更新正式摘要。
- 讀取、寫入與背景工作各自顯示狀態；較舊請求與其他登入帳號的回應不能更新目前畫面。
- 桌面與手機以同一組管理入口、設定分類與動作名稱呈現。

## 實作結果

七個區域均改為用途摘要入口，進入後才顯示設定或紀錄；總覽將統計獨立為「活動與運行狀態」。原有 `?view=` 連結仍可使用，網址、重新載入與同區域的瀏覽器歷史會同步選定區域。

平台設定的五個保留區域各自編輯與還原，整體保留檔位明確說明會修改所有保留期限與清理開關。同一管理頁內切換分類或返回摘要時保留草稿，分類摘要標示未儲存數量。人員區保留已進入的編輯器；多份草稿分別登記，捨棄負責範圍的草稿不會清掉另一個編輯器。

關閉帳號編輯器或使用管理頁的返回按鈕時，會先檢查草稿。儲存中禁止把進行中的請求當作尚未送出的草稿捨棄；程式更新也會等待儲存結束。解除個別帳號規則的確認會明確說明 Email 前綴規則仍可能生效。

範圍成員資料改由一個 PostgreSQL 敘述讀取個人資料、角色與分類權限。管理員判定使用 `ADMIN_EMAILS` 的正式名單；移出名單的帳號可在同一個範圍修改交易中撤銷舊管理員角色，不必等該帳號重新登入。0059 migration 只鎖住被編輯的帳號，不增加全表角色鎖；Email 查詢以正規化索引處理大小寫和前後空白。

分類開關與陣列不再默默套用備用值。錯誤型別會回報驗證錯誤並回滾整次寫入。分類建立後不可變更的可見性與作者顯示方式，在編輯器中固定；快速檔位也僅提供相容的選項。背景進度讀取使用相同的帳號與請求版本檢查，過期回應不能覆蓋目前畫面。

活動紀錄摘要只描述現有的期間與分頁功能。載入下一頁失敗時，保留已載入紀錄並顯示錯誤，重試使用失敗時的同一個游標；錯誤不能被已有資料遮蔽。系統容量頁重新開啟會讀取完整狀態，不把之前只收到佇列片段的快取當成完整容量資料。

## 驗證證據

- `bun run verify:integration`：76 個案例通過；包含正式管理員名單變更、同一批次的原子性、101 位範圍成員、非法設定型別、版本衝突、期限與背景套用。帶資料的舊資料庫升級至 0059，生成資料庫契約相符。
- `tests/unit/admin-setting-presets.test.ts` 核對每個圖片、保留與運行政策檔位是否符合後端契約，以及運行政策檔位的變更範圍。
- 管理操作相關 Playwright 流程：74 個案例通過，包含分類增刪、四種功能開關組合、檔位與還原、設定衝突、限制期限與解除、範圍成員、系統重試、容量重開、草稿離開保護與手機導覽。
- 最後活動錯誤與文案修正：58 個針對性瀏覽器案例通過，新增測試在桌面與手機驗證下一頁失敗仍保留紀錄、沿用同游標重試並清除錯誤。調整截圖流程及移入只讀測試組後，再跑這兩個測試與帳號建置，共 3 個案例通過；一致性檢查仍為 22 項、0 項阻擋。
- 74 案例那一輪的 E2E 資料庫通過 22 項一致性檢查，0 項阻擋：含 8 個帳號、49 個操作、76 個事件、27 個管理稽核、90 個投遞、6 個背景工作、4 個權限範圍及 3 則通知。這些數量僅屬當次測試資料。
- `bun run verify:local`：13 階段通過，含 248 個單元案例、正式版建置、型別、翻譯、架構、工具政策與依賴稽核。最後活動錯誤修正另通過 10 階段快速檢查，正式版重建與針對性瀏覽器驗證。
- 七個區域的繁中 1280 px 與 390 px 畫面、保留期限與運行政策編輯畫面，以及活動錯誤和恢復畫面，共 22 張均保存並開啟核對。畫面證據保存在 `.impeccable/review/`；測試資料使用本機資料庫、登入模擬器與外部服務測試環境。
- Impeccable 獨立介面審查確認分類摘要方向，提出活動摘要能力聲明與分頁錯誤呈現兩項修正；修正後的評分均為 resolved，disposition 為 ship。最後評分僅針對這兩項修正，沒有重新宣稱全面介面審查。

管理畫面與活動錯誤流程可單獨執行，會建立隔離的測試資料與登入環境：

```powershell
$env:NOVAE_E2E_WORKERS = '4'
node scripts/verify-integration.mjs --e2e -- --project=chromium-desktop-readonly admin-workspace.spec.ts
```

瀏覽器的跨路由返回及強制關閉不提供可取消的 App Router 導航事件；離開保護涵蓋頁內連結、管理頁返回與帳號編輯器。寫入的一致性由後端交易與版本核對維持。
