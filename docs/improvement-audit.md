## 需求核對

- **前後端邏輯與可維護性：** 留言、反應、管理讀取、通知資料、session 狀態、realtime 協定與上傳流程已依職責整理。後端採批次資料操作與原子結案，不保留舊的初始化 fallback。架構檢查剩餘的行數提醒位於 list 元件、session 生命週期、提案詳情與連線 transport；這些模組各有一致責任，不為行數再次拆檔。
- **立即回應與動畫：** 操作開始即進入 pending／樂觀狀態；路由、抽屜及內容載入沿用一致的動態與骨架；移除成功後的人為等待。完成發文立即導頁，原表單在導頁完成前仍鎖定，避免重複建立。
- **品牌與介面：** 新 N 對話 Logo、PWA 圖示、校園語氣登入入口，以及桌面頂部導覽，讓內容取得完整寬度。手機保留底部導覽與抽屜。390、768、1024、1440px 均檢查深淺主題、可見導覽及水平溢出；另有 reduced-motion 與快速切換覆蓋。
- **取消、重試與保存：** 初始化及留言可就地重試；上傳部分失敗會清理資源並保留可重試草稿；設定編輯期間收到讀取結果不覆蓋草稿；通知與 session 過期讀取不回寫目前畫面。
- **驗證成本：** 使用既有 Playwright 流程，沒有另開手動瀏覽器。只擴充會出現實際回歸的斷言，最後一批修改只複驗相關管理操作。

- `bun run verify:fast`：10 階段通過（含型別、lint、235 項單元測試與架構／工具檢查）。
- `bun run test:e2e`：正式版建置與完整 85 項 Chromium E2E 通過。
- 最後的管理讀取整理重新建置後，8 項管理操作 E2E 全部通過（另含 1 項帳號與內容 bootstrap）。
- 後端 65 項整合測試、既有資料 migration 升級與資料一致性檢查已在 migration 0052 批次通過；其後修改皆位於前端與測試。

以上驗證使用本機 PostgreSQL、Firebase emulator 與外部服務替身，未宣稱正式 Cloudinary、Notion、FCM 或生產部署已驗證。

## 部署注意

提案結案現在只送一次 `moderateIssueStatus`，終態需附 `resultContent`。部署須先套用 `0052_atomic_issue_moderation.sql`，再發布 Worker 與前端；不要只部署新前端。既有 CI 已依後端完成再發布前端的順序執行。
