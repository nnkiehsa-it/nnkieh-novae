# Novae 平台總管理員｜操作手冊

平台總管理員能管理所有提案與設備分類，也能處理公告、平台規則、人員權限、稽核與系統工作。日常審核提案、更新案件狀態的步驟見[分類管理員操作手冊](category-manager.md)；平台總管理員在那些操作中不受分類指派限制。

## 進入平台管理與總覽

從「設定 → 管理工具 → 平台管理」進入。平台總管理員由後端 `ADMIN_EMAILS` 決定，不能在人員頁把一般帳號改成平台總管理員。

總覽可切換 **24 小時、7 天、30 天**，右上角可重新整理。上方看註冊與活躍人數；「這段期間」列出新註冊、新提案、新留言、新設備案件，點有數字的項目可看活動明細。「查看這段期間的全部活動」會進稽核頁。下方顯示提案分類分布、系統維運狀態，以及六個管理入口。

![平台管理總覽](screenshots/01-platform-overview.jpg)

設定頁另有「平台管理員通知」：留言通知、提案更新、設備更新三個開關只影響目前管理員在這台裝置的偏好，不會替其他人調整。

## 內容與分類

進「內容與分類」，上方切「提案／設備／公告」。這頁採草稿制：更動開關或分類後，底部出現未儲存項數；按「儲存」才送出，按「捨棄」則恢復原設定。若改動會更新既有資料，系統先估算影響筆數，再顯示確認視窗；確認後背景工作分批處理，可到系統工作進度查看。

![提案分類列表與總開關](screenshots/02-content-issue-list.jpg)

### 提案功能與分類

1. **提案功能開關**：關閉會隱藏一般使用者的提案入口，既有分類與提案保留。再次開啟後繼續使用。啟用時至少要有一個有效分類，且恰好一個預設分類。
2. **新增分類**：按「新增提案分類」，列表會先多出未儲存草稿。打開草稿，填名稱與識別碼，再選閱讀權限、作者顯示、留言、附議與作者刪除規則。識別碼只能用小寫英數及中間連字號，不能重複；名稱不可空白，最多 40 字。
3. **修改分類**：點分類列可改名稱、預設分類、作者刪除、留言與附議。已儲存的識別碼鎖定。分類建立後，閱讀權限與作者顯示也被後端固定；即使畫面上的控制項可點，送出這兩項變更仍會被拒絕。需要不同隱私規則時，先建立新分類。
4. **預設分類**：在分類詳情選「預設分類」，新提案會預選它；原預設會取消。預設分類不能直接刪除。
5. **刪除分類**：先指定其他預設分類，再按「刪除分類」。第一次確認只把刪除加入草稿；底部再次按「儲存」才執行。既有分類下的提案、留言、附議、通知與圖片會永久刪除。按「取消」或在儲存前按「捨棄」可保留原資料。

**閱讀權限如何組合**

- **全校可見**：送出後全校可看，不經審核。若有附議，期限從建立時起算。
- **審核後全校可見**：先是「待審核」，作者與該分類管理員可看；通過後全校可看，附議期限從通過時起算。退件後仍不公開。
- **僅作者與管理員**：不進其他學生的列表。此模式下後端強制顯示作者，不能用「隱藏作者」讓管理員看不到身分。
- 對前兩種閱讀權限，關閉「顯示作者」只隱藏一般讀者看到的身分；作者本人與管理員仍能辨識。

**留言、附議與作者刪除如何生效**

- 關閉分類留言會排背景工作，把既有提案的新留言入口一併關閉；重新開啟不會重開已結案、退件或其他個別關閉的案件。
- 附議開關、門檻與天數只影響**此後建立**的提案。啟用時門檻與天數都須填正整數；作者送出時自動算入 1 人。修改分類設定不會重算既有案件的門檻或期限。
- 開啟「允許提案人刪除自己的提案」後，作者可刪自己的案件；有該分類管理權限的人始終可刪。這是刪除單一提案的權限，與刪除整個分類不同。

### 設備與公告設定

設備有獨立的功能開關、分類、預設分類及作者刪除規則。關閉設備功能會隱藏入口並停用新增分類，既有資料保留；目前學校的設備功能是關閉狀態。正式啟用時須有至少一個有效分類和一個預設分類。刪設備分類會永久刪除其下案件與關聯資料。

公告沒有分類；這裡只有「公告留言」開關。關閉後會以背景工作更新既有公告的留言狀態。發布與刪除公告的授權則由「公告管理」權限決定。

## 平台設定：資料保留與圖片

進「平台設定」後切「資料保留／圖片上傳」。修改先成草稿；資料保留若會清理既有紀錄，儲存前會顯示估算筆數與確認視窗。每項清理開關開啟後才顯示對應期限。

- **內容生命週期**：已結案提案、已結案設備案件、舊公告、舊通知。
- **帳號與隱私生命週期**：閒置頭像、閒置個人資料、到期限制，以及推播裝置的保留與確認間隔。
- **系統運作紀錄**：完成／失敗投遞、操作、事件、完成／失敗背景工作。
- **稽核歷史**：角色指派、平台管理動作、分類設定、存取指派。
- **上傳生命週期**：待上傳、未附加、失敗上傳資料。

## 人員與權限

「依帳號」可用姓名、校內信箱或 UID 搜尋已登入過的帳號；點開可看 UID、註冊時間、角色、負責範圍及生效中的限制。對外分享畫面前先遮蔽姓名、學號、信箱和 UID。

![帳號搜尋入口](screenshots/16-people-search.jpg)

### 依範圍指派管理員

1. 切「依範圍」，先選**提案分類／設備分類／公告管理**。前兩者還須選具體分類；公告管理是全域範圍。
2. 查看目前負責人。按右側撤銷圖示會把撤銷放進草稿。
3. 在「尋找並指派成員」用姓名、校內信箱或 UID 搜尋；選到候選人後按指派。已在此範圍的人會顯示已授權。
4. 底部按「儲存」才生效；「捨棄」取消草稿。重新進入同一範圍確認名單。

同一人可同時持有多個提案、設備分類與公告權限；授權只在指派的範圍生效，不會讓他修改平台分類政策。

### 帳號限制

「依帳號」可對單一 UID 設限制；「限制規則」可用校內信箱 @ 前的**前綴**，持續匹配現在及未來的新帳號。單一 UID 規則優先於前綴規則。平台總管理員不受這些互動限制。

- **唯讀**：可以閱讀，但不能新增、留言、上傳或附議、按讚等反應。
- **僅可反應**：仍可附議、公告按讚和標記「我也遇到」，不能新增、留言或上傳。
- **完全封鎖**：受保護的請求會被拒絕。

操作時先填目標、模式及期限（7 天、30 天、自訂或永久），再填**會顯示給使用者的原因**後套用。自訂期限要填時數。前綴規則建立後不能改前綴，須刪除並另建。套用前檢查符合人數，避免前綴過短。

## 稽核紀錄

切「管理動作／平台活動」。管理動作可搜尋並打開一筆，看執行者、時間、操作、目標 ID 與細節；平台活動看選定期間的內容與帳號活動。審核或刪除提案、變更分類、指派權限、修改平台政策與系統清理等都會留下管理動作紀錄。

## 系統運作

「失敗與重試」列出排隊中或卡住的背景工作、事件投遞與 Worker 錯誤。失敗工作可開詳情後單筆重試，或整批重試；Worker 錯誤紀錄用來查請求錯誤，不能在該列重試原請求。

![失敗與重試](screenshots/25-system-failures.jpg)

「排程重建」會完整重寫 Notion 封存的目前內容、狀態、時間、留言及維運紀錄。確認視窗會說明：舊 Notion 同步佇列、失敗紀錄與前次重建先清掉；其他通知佇列不受影響。既有 Notion 頁面不會自動刪除。送出後看背景工作進度。

![Notion 封存重建確認](screenshots/26-system-notion-rebuild-confirm.jpg)

「清除所有排程」會停止等待中、執行中與失敗的背景工作並清掉外部刪除待辦；已完成歷史與未來新增的工作保留。「清除所有 Worker 錯誤」只清掉目前的錯誤統計。兩個操作各有確認視窗。

![清除排程確認](screenshots/27-system-clear-schedule-confirm.jpg)

「容量」顯示資料庫總量、近期樣本與主要資料表，按「全部」查看每張表的列數、待清版本與大小。「外部服務」可查看 Cloudinary 用量、Cloudflare Workers 統計與原始回應；Worker 日誌需輸入追蹤 ID 或事件關鍵字才會搜尋。

## 運行政策

這裡控制實際請求、配額、快取、背景批次與即時連線。先改數值，底部會出現未儲存項目與**變更原因**；原因填妥才能儲存。每次成功儲存產生新 revision，可從「設定修改紀錄」看前後差異。

- **內容**：標題、內文、留言、處理結果、地點和搜尋長度。
- **配額**：每 10 秒讀寫／管理／圖片操作，以及每日或每小時提案、設備、公告、留言、附議、通知、刪除等限額。
- **進階**：Notion 事件與錯誤保存、前端快取和請求逾時、重試、工作批次、即時連線憑證。

## 公告發布與刪除

平台總管理員到「公告 → 新增公告」，填標題與內容，必要時加圖片，確認後按「發布公告」。工具列可用標題、粗體、斜體、清單、連結與更多格式。文字草稿在此分頁保留最多 24 小時；離開後圖片要重新選取，登出會清掉草稿。既有公告詳情右上「更多操作」可刪除；若公告留言開啟，可回覆及管理留言。單獨取得「公告管理」授權的人也能做這些公告操作，但不能進平台設定頁。
